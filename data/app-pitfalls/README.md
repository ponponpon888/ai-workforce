## idem-002 を自分のリポジトリで見る

`idem-002`（効いていない冪等キー）だけは、対象コードを読むだけで当てられます。

```
node kit/scripts/check-idem-002.mjs --root ../your-app
node kit/scripts/check-idem-002.mjs --root ../your-app --json
```

`--root` の下の `.js` / `.mjs` / `.cjs` を読み、**受信ごとに増えるログ行の id を、配信とともに届く
id より先に選んでいる**冪等キーを報告します。`--root` の中身を import・実行することはなく、
対象側の設定ファイルも読みません。

指摘するのは、次の 3 つがそろったときだけです。1 と 2 は同じ関数の中にある必要があります。
名前だけでは判定しません。

1. `.insert(...).select('id')` から束縛された行 id（payload に `id` が無く、配信ごとに新しい）
2. その行 id を `||` / `??` の**先頭**で選び、配信由来の id を後ろに置く式
3. その値が実際に `idempotency_key` へ渡っていること（同じ関数の中、または次の形の呼び出し先）

別ファイルへは、`fn({ sourceKey: key })` のようにオブジェクトのプロパティで渡し、受け取り側が
`export function fn({ sourceKey })` と分割代入している経路を 1 段だけ追います。
`` idempotency_key: `message:${sourceKey}` `` のようなテンプレートも使用と見なします。
報告には呼び出し元と受け取り先の相対パスと行番号が付きます。

`@/x` は設定ファイルを読まず、`--root` の下の `src/x` と `x` だけを探します。追えるのは
`--root` の下で読んだファイルだけです。両方にある場合や、受け取り側が見つからない場合は、
0 件ではなく `3` にして `unresolved` に理由を出します。

終了コード: `0` 読めて該当なし / `1` 該当あり / `2` 呼び出し誤り / `3` 不完全（読める候補が
0 件、読めなかった候補がある、または該当しうる値を渡した呼び出しを追えなかった）。`3` を `0` と
分けているのは、「見ていない」と「見たが何も無かった」が別の答えだからです。

このレコードの `detection.checkable` は `false` のままです。当てる先は読む人のアプリであって
このリポジトリではなく、`lint-pitfalls` は自分のルートの決まったパスしか読みません。
