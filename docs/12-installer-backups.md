# 12. 再インストール時のバックアップ

既存ファイルを置き換える前に、同じディレクトリへ
`元のファイル名.bak.時刻.一意ID` という名前でコピーします。
Node版・PowerShell版とも、コピーは既存バックアップの上書きを禁止します。
コピーがエラーになった場合、その対象ファイルの書き込みには進みません。

従来は秒単位の時刻だけで名前を決めていたため、同じ秒に再インストールすると
最初のバックアップを次のバックアップで上書きしていました。
今回から一意IDを追加し、同時刻でも履歴を別ファイルとして保持します。
以前の形式のバックアップも削除・上書きしません。

```powershell
node kit/scripts/test-install-backups.mjs
node kit/scripts/test-install-backups.mjs --target ps
node kit/scripts/test-install-backups.mjs --target ps --pwsh powershell.exe
```

テストは一時ディレクトリ内だけでインストーラを実行します。時計を固定して連続実行し、
2世代の元ファイルをバイト単位で保持すること、旧バックアップが残ること、
試行実行で作成しないこと、スキップ指定した設定・説明ファイルを変更しないことを検査します。

バックアップは自動削除しないため、内容が異なるファイルを繰り返し更新すると増えます。
設定の自動マージやインストール全体のロールバックは行いません。
既存の設定を保持してフックを手動追加する場合は、Node版の `--skip-settings`、
PowerShell版の `-SkipSettings` を使用してください。
この変更は複数インストーラの同時実行を排他制御するものではありません。

Node版は書き込み前に全引数を検証します。未知のオプション、値の欠落・空文字、
同じオプションの重複、余分な位置引数は終了コード1で停止します。
`--dryrun` のようなタイプミスを無視して実インストールすることはありません。
値は `--claude-home "C:/work/claude"` のように別の引数として渡してください。

両インストーラは、選択された配布ファイルをすべて読み込み、展開後の設定がJSONオブジェクト
として解析できることを確認してから、バックアップと書き込みを開始します。配布ファイルの欠落や
不正JSONがある場合は、既存の導入先を変更しません。設定スキーマ全体の検証は行いません。
書き込み開始後のディスク障害などはロールバックしないため、全体が不可分な更新ではありません。

PowerShell版で `-Confirm` を使い、ディレクトリ作成やバックアップを断った場合、
そのファイルの更新をスキップします。バックアップを断った後に上書きだけを承認する
経路はありません。`-WhatIf` は引き続き予定を表示し、書き込みません。
確認を断った場合は全体中断ではなくファイル単位のスキップなので、ログを確認してください。

Node版の設定テンプレートは1回の置換で展開し、保存先の `$&` などを置換命令として
解釈しません。JSONの文字列エスケープは標準のシリアライザを使用します。
これは設定JSONの生成処理の保証であり、任意のパスでのシェル実行を保証するものではありません。

両インストーラは書き込み前に既存ファイルと出力予定のUTF-8バイト列を比較します。
同一なら `unchanged` と表示し、バックアップ・書き込み・更新確認を省きます。
ファイルの更新日時も保持します。BOMや改行の違いは変更として扱います。

両インストーラは選択された全出力先を検査し、出力先が既存ディレクトリの場合や、
親ディレクトリとして使う場所が既存ファイルの場合、最初の書き込みより前に停止します。
この検査は書き込み権限・容量・並行変更を保証しません。

テストには導入後の接続確認も含みます。空白を含む一時フォルダへ導入し、生成された
settings.jsonのBash対象コマンドからNodeフックを起動します。危険なSQLと機密ファイル
読み取りの拒否、参照SQLと通常ファイル読み取りの許可を確認します。入力コマンドは
JSONデータとして渡すだけで、データベース操作やファイル読み取り自体は実行しません。
PowerShellインストーラのテストでも既定のNodeフックを使用します。Claude Code本体が
設定を受理して呼び出すことや、PowerShellフックの接続を検証するものではありません。
