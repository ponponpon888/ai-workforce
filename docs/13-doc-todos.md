# 13. 文書の未完了マーカー

`node kit/scripts/check-doc-todos.mjs` は、README.md、README.en.md、docs以下のMarkdownを検査します。
書き込みは行いません。終了コード0はマーカーなし、1はマーカーあり、2は入力を検査できない状態です。

未完了事項は行頭に `TODO:` または `TODO(担当):` と書きます。見出し、リスト、チェックボックスの
接頭辞にも対応します。コード例はバッククォートまたはチルダのフェンスで囲んでください。

```markdown
TODO: 説明を追加する
- [ ] TODO(owner): 測定する
```

従来の全件文字列検索と異なり、文中の言及やインラインコード、行頭から3スペース以内で始まる
フェンス内のコード例、4スペースまたはタブで始まるコード行を拾いません。
完全なMarkdownパーサではありません。引用ブロック・入れ子リスト内のマーカーは対象外となる場合があります。
フェンスが閉じていない場合は、その後をコード例として扱います。Markdownの構文検証は行いません。

`node kit/scripts/test-check-doc-todos.mjs` で判定のテストを実行します。
テストは既存のpitfallsジョブで必須検査として実行し、文書中の未完了項目は既存todosジョブの
continue-on-errorに従い警告扱いを維持します。ジョブ数は増やしません。

## リンクが解決すること

`node kit/scripts/check-doc-links.mjs` は、同じ範囲（README.md、README.en.md、docs 以下の
Markdown）の**相対リンクが実在するファイルを指しているか**を検査します。書き込みは行いません。
終了コード0はすべて解決、1は未解決あり、2は入力を検査できない状態です。

検査するもの:

- インラインリンクと画像、参照定義の**相対パス**（`[x](a.md)`、`![alt](img.png)`、`[x]: a.md`）
- そのリンクに `#見出し` が付いていて、指す先がこのリポジトリ内の Markdown のときは、**見出しが
  実在するか**も見ます。見出しの照合規則は落とし穴レコードの `origin` と同じ実装
  （`kit/scripts/markdown-anchors.mjs`）を使います。2つ持つと、見出しに記号が入った瞬間に
  食い違い、文書とレコードが別々の規則で検査されることになるためです

検査しないもの:

- `http(s):` と `mailto:` — ネットワークに出ると、変更と関係のない理由で落ちるようになります
- フェンス内のリンク — コード例であって、リンクではありません

入れた理由は、**実際にリンク切れが2本出荷されたから**です。`docs/02-guardrails.en.md` が
`](data/pitfalls/hook-010.json)` と書いていて、日本語の正本にある `../` が落ちていました。
docs/ の中からは解決しません。誰も気づかなかったのは、リンクを見る仕組みが無かったからです。
英訳を増やすたびに、別のディレクトリ基準で書かれたパスを写す機会が増えます。

判定のテストはこう実行します。件数は散文ではなくコマンドの隣に書きます。下の節の検査が、
実際に走らせて照合するからです。

```bash
node kit/scripts/test-check-doc-links.mjs   # pass: 30   fail: 0
```

## コマンドの隣に書いた結果が本当か

README は、実行するコマンドのすぐ隣に、そのコマンドが出す結果を書いています。

```bash
node kit/scripts/test-guard-sql.mjs    # pass: 94   fail: 0
```

誰も走らせていなかったので、古くなりました。この検査を入れた時点の実測では、guard-sql は
**91**、guard-config は **53** を出していたのに、README.md と README.en.md の**10箇所のうち
6箇所**が 87 と 45 のままでした。コマンドを実行した読者は、それを読んでいるページと違う数字を
見ることになります。「思い込まずに測れ」と書いてあるページで、です。

[doc-001](../data/pitfalls/doc-001.json) と同じ形の、ひとつ外側です。あちらは散文がレコードの
フィールドを引用したまま古くなり、こちらは散文がコマンドの出力を引用したまま古くなりました。
どちらも人間への注意書きとして書かれ、どちらもずれました。直し方も同じで、**散文が主張して
いることを機械に読ませます**。

```
node kit/scripts/check-doc-commands.mjs
```

新しい記法は作っていません。`# pass: N   fail: N` はこのリポジトリが元から使っていた書き方で、
この検査はそれを実行するだけです。

検査するもの:

- フェンスの中にある `node kit/scripts/test-<name>.mjs   # pass: N   fail: N` の行すべて
  （範囲は `check-doc-links` と同じ）

検査しないもの、とその理由:

- **フェンスの中の、それ以外の行。** 実行するのは実在する `kit/scripts/test-*.mjs` だけで、
  引数を文書から取ることは決してしません。ページに書いてあるものを走らせる検査は、
  **ページを編集すれば何でも実行できる仕組み**になります。テストの大半はこの一点にあります
  （`node ../evil.mjs`、`kit/scripts/../../evil.mjs`、`test-a.mjs; rm -rf /`、
  `test-a.mjs --root /` が、いずれも**認識すらされない**ことを見ています）
- **PowerShell 版。** この書き方は `node` の行にしか使われておらず、`pwsh` はこの検査が
  走りうるすべての環境にあるとは限りません
- **コマンドの隣ではなく散文に書かれた件数。** 走らせる相手が無いので、古くなっていたものは
  コマンドの隣へ移しました。それがこの変更で `docs/00` と `docs/02` にやったことです

実測してわかったのは、**壊れるのは合計値だけ**だということです。内訳（止める 42 / 通す 32 /
承認トークン 11 など）は今も正しく、合計だけが 87・45・44・23 と古くなっていました。
ケースを1件足すたびに変わるのは合計値なので、当然といえば当然です。だから合計は
**コマンドの隣に一度だけ**書き、他の場所からは消しました。

### なぜ専用のワークフローなのか

`test.yml` は `**/*.md` と `docs/**` を `paths-ignore` に入れています。無料枠を使い切った
ことがあり、macOS の単価が Linux の約10倍だったためです
（[ci-001](../data/pitfalls/ci-001.json)）。その副作用として、**文書だけの変更では CI が
1つも走りません** — リンクを壊すのはまさにそういう変更です。

そこで文書の検査は `.github/workflows/docs.yml` に分けました。Ubuntu 1ジョブのみ、数秒です。
`check-doc-todos` も同じ理由でこちらに入れてあります（文書だけの PR では今まで走っていません
でした）。
