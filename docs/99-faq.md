# 99. FAQ

### エンジニアじゃないのに、本当に本番で動いてるの？

動いています。稼働中のサービスは [事例](case-studies/) に載せています。
名前を伏せているものもありますが、構造とコードの形は出しています。

私にできないのは「コードを読んで間違いに気づくこと」であって、
「何を作るか決めること」と「壊れない構造を用意すること」は別の能力です。
このリポジトリは後者の話です。

### crewAI / AutoGen / LangGraph とどう違うの？

競合しません。あれはエージェントを組む**ライブラリ**、これは AI に開発をさせる**運用一式**です。
このリポジトリの中身は、設定ファイル、フック、スクリプト（Node と PowerShell）、運用ルール。
Python のパッケージは 1 つも入っていません。

### Mac / Linux では使えないの？

フックとインストーラは使えます。

```bash
node kit/scripts/install.mjs --dry-run
node kit/scripts/install.mjs
```

`guard-sql.mjs` は Node で動きます。Claude Code 自体が Node で配布されているので、
追加でインストールするものはありません。bash や jq や python も要りません。
CI で Ubuntu / macOS / Windows の 3 つで回しています。

`pull-all` も Node 版（`pull-all.mjs`）があります。cron に 1 行足すだけです。

```cron
@reboot sleep 60 && /usr/bin/node ~/Dev/ai-workforce/kit/scripts/pull-all.mjs --root ~/Dev --quiet
```

`settings.json` の `deny` には Windows 固有の行（`Remove-Item` など）が混ざっています。
Mac / Linux では無害なので放置で構いませんし、消しても構いません。

### Claude Code 以外（Cursor / Codex / Copilot）でも使える？

`CLAUDE.md` の中身（安全ルール、報告の義務、先回りして入れるもの）は
どのツールでも通用します。ルールファイルの名前を置き換えるだけです。

`settings.json` と `PreToolUse` フックは Claude Code 固有です。
同等の仕組みがあるツールなら移植できます。

### フックは AI に回避されないの？

されます。[02 機械的な歯止め](02-guardrails.md) の冒頭に書いた通り、
**これは事故を止める仕組みであって、悪意を止める仕組みではありません。**

シェルを持ったエージェントは原理的に回り込めます。承認トークンを自分で書くこともできる。
それでも意味があるのは、実際に起きるのが悪意ではなく、うっかりだからです。

本気で止めるなら、権限そのものを落とすのが正解です。
Supabase についてはやり方が分かったので、[06](06-supabase-mcp.md) に書きました。
接続を読み取り専用にしてしまえば、AI が何を書こうが書き込みは通りません。

### 承認をスキップして怖くないの？

怖いです。チャット側には機械的な歯止めがほとんどありません
（[03](03-division-of-labor.md) の末尾）。

ただ、確認を毎回出していた頃の方が、実は危なかったと思っています。
確認が多すぎると、読まずに OK を押すようになる。形骸化した確認は、確認していないのと同じです。

いまは「取り消せない操作だけ止める」に線を引き直して、
残った確認は全部ちゃんと読んでいます。回数が 1/10 になったので読める。

ただし、承認を切るなら切った分だけどこかで埋め合わせが要ります。
それをやっていなかったので、いま順に潰しています（[06](06-supabase-mcp.md)）。

### なぜ無料で全部出すの？

作ったものを見せる以外に、私が本物だと示す方法がないからです。

経歴は非エンジニアで、資格もなく、有名企業にいたわけでもありません。
残っているのは「動いているもの」と「その作り方」だけです。だから出します。

### 仕事の依頼はできる？

できます。[shingokumon.com](https://www.shingokumon.com) から。国内・海外どちらでも。

### PR は受け付けてる？

はい。特に:

- bash / zsh 版のスクリプト
- 他のデータベース（MySQL、SQLite）向けの `guard-sql` 対応
- あなたが踏んだ「既知の落とし穴」

「自分の環境ではこうした」という報告も歓迎です。Issue で構いません。

書いてあることが間違っている、という指摘も同じくらいありがたいです。
実際このリポジトリは、一度「Supabase 側でロールを分けて `GRANT` を落とせばいい」と
書いていました。効きません（[06](06-supabase-mcp.md)）。

詳しくは [CONTRIBUTING.md](../CONTRIBUTING.md)。
