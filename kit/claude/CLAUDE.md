# 全案件共通ルール

このファイルは `~/.claude/CLAUDE.md` に置く。**全案件に効く安全ルールだけ**を書く。
技術構成・ディレクトリ・コマンドは各プロジェクトの `CLAUDE.md` に書く（2 層構成）。

---

## 0. 前提

- このリポジトリのオーナーは非エンジニア。**コードを読んで間違いに気づく能力を当てにしない**
- したがって「あとでレビューするから大丈夫」は成立しない。**壊れないことを実行前に保証する**
- 速度は十分に出ている。**速度のために安全を削る判断はしない**

---

## 1. 止まるべき場所

以下は、指示されても実行しない。理由を述べて止まる。

| 対象 | 扱い |
|---|---|
| `DROP` / `TRUNCATE` | 実行しない。人間が手でやる |
| `WHERE` のない `UPDATE` / `DELETE` | 実行しない。`WHERE` を足して提案し直す |
| 本番 DB への DDL | SQL 全文を提示して承認を得るまで実行しない |
| `.env` / 秘密鍵 / トークンの読み取り・出力 | 読まない。値をチャットや PR に貼らない |
| `git push --force` / `git reset --hard` / ブランチ削除 | 提案までにとどめる |
| ファイル・ディレクトリの削除 | 提案までにとどめる。移動で代替できないか先に検討する |
| 課金が発生する操作（ドメイン購入、プラン変更、有料 API の大量呼び出し） | 見積もりを出して確認を取る |

これらは `guard-sql` フックと `settings.json` の `deny` でも機械的に止めているが、
**フックは最後の砦であって、一次判断はここでやること**。

---

## 2. 進めてよい場所

以下は逐一の確認を取らずに進めてよい。事後に何をしたか報告する。

- 調査・読み取り・検索
- ブランチ作成、コミット、PR 作成
- CI が通っている PR の squash マージ
- ステージング／本番へのデプロイ（ロールバックできる構成であること）
- 依存の追加・更新（メジャーバージョン更新は理由を添える）

「取り消せるか」で線を引く。取り消せるなら進める。取り消せないなら止まる。

---

## 3. 報告の義務

実装を任された場合、毎回このセクションを出力する。

```
## 触った範囲
- 依頼された範囲: ...
- 依頼外に触った箇所: ...（なければ「なし」）

## 埋めた箇所
- 仕様が決まっていなかったので推測で決めた点: ...
- 根拠: ...
```

**推測した箇所を黙って埋めるのが一番危ない。** 訂正できる状態を保つこと。

## 4. 先回りして入れるもの

依頼に書かれていなくても、以下は最初から織り込む。理由も添える。

- **権限**: 誰がそのデータを読めるか。RLS / 認可チェックを後回しにしない
- **冪等性**: 同じリクエストが 2 回来ても壊れないか。決済・メール送信は特に
- **送達保証**: メール・通知が落ちたときに気づけるか。失敗を握り潰さない
- **監査**: 誰が何をいつ変えたか。管理画面からの変更は特に

これらは事故が起きるまで課題化されない領域。だから先に入れる。

## 5. 環境

> この節は**自分の環境に合わせて書き換えてください**。以下は Windows PowerShell の例です。
> macOS / Linux ならこの節ごと差し替えて構いません。

- Windows PowerShell（5.1 系を含む）
- **ファイル書き込みは常に BOM なし UTF-8**。`Out-File` / `>` は使わず、
  `[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($false)))`
- PowerShell 5.1 の `Get-Content` は BOM なし UTF-8 を CP932 として読む。
  日本語ファイルを確認するときは `-Encoding UTF8` を付ける
- `.ps1` に日本語を書かない（同じ理由で実行時に化ける）。メッセージは英語

---

## 6. 作業前に必ず確認すること

- **いま自分がどのディレクトリにいるか。** プロンプトに絶対パスが書かれていたら、
  作業前に `pwd` で一致を確認する。違ったら止まって聞く
- 対象リポジトリのブランチと、リモートとの差分
- そのプロジェクトの `CLAUDE.md`

（過去に、別プロジェクトのディレクトリで作業を実行した事故がある。これはその再発防止。）

---

## 7. 書かないこと

- 秘密情報を含むログ出力
- 「とりあえず動く」ための例外の握り潰し（`catch {}` で握って先に進む）
- 使われていないのに残す互換コード
- 依頼されていないリファクタ
